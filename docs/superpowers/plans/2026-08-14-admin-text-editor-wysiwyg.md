# Admin TEXT Editor WYSIWYG Parity Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace the administrator's current `TEXT Editor 작성` textarea with a shared WYSIWYG editor that matches the ZeroSourcing administrator editor's authoring behavior, persists a canonical document safely, supports managed body images, and renders the same result on every public detail page.

**Architecture:** Port the proven managed-content boundary from the read-only reference `/Users/sangkun/nocoders/zerosourcing-v2` at commit `2ffd0bee27082bac5320bcfc0d340163fc39b99a`, while adapting its UI to C-Brain's `design.md` and existing `AdminIcon` pattern. Tiptap JSON is the editable canonical source and generated HTML is the public snapshot; additive Postgres columns distinguish legacy Markdown/raw HTML from WYSIWYG without rewriting existing content. A record-scoped Storage path owns every editor image, and the public Next.js app sanitizes WYSIWYG HTML again before rendering it inline.

**Tech Stack:** React 19, Vite 8, TypeScript 5.9/6, Tiptap 3.27.1, Next.js 16 App Router, Supabase/Postgres JSONB and Storage, Vitest/jsdom, Node test runner, CSS Modules.

## Global Constraints

- Apply the shared editor to Blog, Notice, Portfolio, Interview, and Testimonial content fields; do not create separate editor implementations per page.
- Keep the visible mode labels `HTML 작성` and `TEXT Editor 작성`. Internally they map to `raw_html` and `wysiwyg` authoring modes.
- New content starts in WYSIWYG mode. Existing `content_mode = 'html'` rows remain raw HTML; existing `content_mode = 'markdown'` rows remain legacy TEXT until an administrator explicitly converts them.
- Reconcile both repository database histories: the older migration enum value `text` becomes the canonical `markdown` value without changing the `content` bytes, while already-canonical `html | markdown` databases remain unchanged.
- WYSIWYG rows always persist `content_mode = 'html'`, canonical `content_json`, generated HTML in `content`, schema version `1`, and one immutable UUID asset scope.
- Never silently parse or overwrite existing raw HTML/Markdown when modes change. Retain the inactive source/document so switching modes cannot destroy authored work.
- Match the ZeroSourcing feature contract: undo/redo; H2/H3/H4; bullet and ordered lists; blockquote; horizontal rule; bold/italic/underline/strike; safe links; left/center/right alignment; button, paste, and drop image upload; image alt/decorative review.
- Body images accept only PNG, JPEG, and WEBP up to 10 MiB and use `public-assets/content/{entity}/{scope}/images/{uuid}.{ext}`. Do not accept base64, blob, arbitrary external, or sibling-scope URLs as persisted image sources.
- Draft behavior must preserve current domain rules. Publication additionally requires all WYSIWYG uploads to be complete and every image to have reviewed accessibility metadata.
- Where raw HTML is rendered (Blog and the dirty-worktree Portfolio detail), it must be isolated by a sandboxed frame or an equivalent sanitizer boundary; Review and Notice retain their current safe legacy block fallbacks. WYSIWYG HTML is sanitized server-side before inline rendering even though it was generated by Tiptap.
- Follow `design.md`: Pretendard GOV typography, parent `gap` spacing, SVG/currentColor icons, no child margins for normal layout, and no new focus border/outline/box-shadow styling.
- Add editor glyphs to `apps/admin/src/components/AdminIcon.tsx`; do not copy ZeroSourcing's unused Tiptap template/icon tree or add raster UI icons.
- Preserve every pre-existing dirty-worktree change. In particular, re-read `adminAssets.ts`, `publicAssetPath.ts`, `PortfolioFormPage.tsx`, `portfolioData.ts`, `apps/user/lib/publicContent.ts`, the Portfolio detail page, and their tests before implementation; merge around the ongoing Portfolio asset/file-name work rather than reverting it.
- Do not retain any Figma MCP asset URL in source. The final Figma URL scan must return no matches.
- The database migration must deploy before code that writes the new columns. Do not mutate the connected database while implementing unless the user separately authorizes migration execution.

- [ ] **Step 4: Write the backward-compatible SQL migration and update the fresh baseline**

Do not edit the already-published old migration. In the new migration, repeat this sequence for `posts`, `portfolio_items`, and `reviews` so either starting shape converges safely:

```sql
alter table public.posts drop constraint if exists posts_content_mode_check;
alter table public.posts alter column content_mode drop default;
alter table public.posts alter column content_mode type text
  using case
    when content_mode::text = 'text' then 'markdown'
    else content_mode::text
  end;
alter table public.posts alter column content_mode set default 'html';
alter table public.posts add constraint posts_content_mode_check
  check (content_mode in ('html', 'markdown'));
```

Run the equivalent statements with table-specific constraint names for the other two tables. This changes only the legacy mode label, never `content`. Then add the five columns, set all existing rows to `raw_html`, generate a different UUID scope per row, retain canonical `html | markdown` values, and add named constraints:

```sql
check (content_authoring_mode in ('raw_html', 'wysiwyg'))
check (content_schema_version = 1)
check (
  content_authoring_mode <> 'wysiwyg'
  or (
    content_mode = 'html'
    and content_json is not null
    and jsonb_typeof(content_json) = 'object'
    and content_json ->> 'type' = 'doc'
  )
)
```

Do not broaden Storage policy in this migration. Because these tables are publicly readable, revoke table-wide anonymous access, grant `anon` only the existing public columns plus `content_authoring_mode` and `content_asset_scope`, and explicitly exclude `content_json`, `content_source_backup`, and `content_schema_version`; narrow the published-row policy to `anon` while keeping the existing authenticated admin policy. Build the migration's column grant from columns that actually exist so both the enum-backed legacy history and current baseline are supported.
